Discount codes for an event: how to use them without giving the sale away

By SOMOS DER · October 29, 2026 · 6 min read

A well used discount code moves tickets that were not going to sell. Badly used, it lowers the price for people who would have paid full price anyway. The difference is not in the percentage but in three things: who you give it to, how many times it can be used and until when it is valid. Here is how to think about it and what ENTRÁ lets you configure.

A note before you start: ENTRÁ is an Argentine ticketing platform. It sells tickets for events held in Argentina, priced in Argentine pesos (ARS). What this guide says applies to most events; when it describes how ENTRÁ works, it means in Argentina.

First: what you want the discount for

Before inventing a code, answer one question: whose price are you lowering, and why? If you don't have an answer, the discount ends up in the hands of people who were going to buy anyway. The uses that make sense are few:

  • Rewarding a specific group. Your followers list, people who came to the previous date, club members, workshop students.
  • Unblocking a tier that won't take off. A short-lived code to push the first days of sales.
  • Giving something to whoever promotes. Each band on the lineup or each person who drives the event gets their own code, so everyone has something to offer.

If what you want is for everyone to pay less at the start, that is not a code: it is a cheaper tier. To set up prices and tiers, see how to price your tickets.

What ENTRÁ lets you configure

Codes are created in the Descuentos (discounts) tab of the event dashboard. Each code has:

  • The code text. It is saved in capital letters and cannot be repeated within the same event. It belongs to that event only: it does not work for another.
  • The type: percentage or fixed amount in pesos. In both cases the discount applies to the subtotal of the whole purchase, not per ticket, and it can never take it below zero.
  • A usage limit, optional. If you leave it empty, the code has no cap.
  • An expiry date, optional. If you leave it empty, the code is valid while it is active.

Once created, in the list of codes you can pause it and reactivate it, or delete it. Each code shows its status (active, paused, expired or used up) and how many times it was used against its cap. A code cannot be edited: if you got the value wrong, you delete it and create another.

One detail that matters: codes do not apply to free events, because there is nothing to discount.

The three safeguards that keep you from giving the sale away

1. Usage cap

A code with no cap that leaks into a big group ends up selling the whole event at a discount. Always set a limit. Keep in mind how ENTRÁ counts:

  • It counts purchases, not tickets. If one person uses the code and takes four tickets, that is one use. If your idea is "ten discounted tickets", a cap of ten can end up as quite a bit more than ten tickets.
  • The use is counted when the person starts paying, not when they finish. If someone starts the purchase and abandons it, that use has already been counted. Leave some margin.

2. Fixed amount or percentage

Since the discount applies to the purchase total, a fixed amount applies only once per transaction, whether they buy one ticket or six. A percentage grows with the purchase: the more tickets, the bigger the discount. If you want to reward groups that buy together, the percentage works. If you want to limit how much you give away per person, the fixed amount is tidier.

3. Expiry

A code valid until the day of the event competes with your own full price sales. Give it a date. Watch how it is loaded: the field asks only for the day, and the code stops working at the start of that day, not the end. Treat the date as the first day it is no longer valid: if you want it to work through Friday, enter Saturday.

If something gets out of hand early (the code showed up in a group it was not meant for), don't wait for it to expire: pause it from the list and that's it.

The code can't be forced

The buyer types the code at checkout and sees the discount applied. But what sets the price is not the buyer's screen. When the payment is created, the ENTRÁ server looks up the code again for that event and checks that it is active, not expired and not over its cap. If any of that fails, the purchase goes through at the normal price. The discount is also saved in the order, together with the code used.

How to know which code sold

The direct way is the usage column for each code in the dashboard. That is why it is worth having a different code per group or per person who promotes: "BAND1", "BAND2", "MEMBERS". At the end of sales you know who moved tickets and who didn't, which helps you decide who to work with again.

Now, if all you want is to track where sales come from, a code is an expensive way to do it: to find out which channel worked, you are lowering every buyer's price. ENTRÁ stores where each sale came from. If you share the event link with utm parameters (for example, utm_source with the network and utm_campaign with the name of the action), the order records it: the dashboard shows it in the where sales came from block and the sales export includes the source and campaign columns. You measure without giving anything away. More on this in how to promote an event and track sales.

The practical rule: a code to reward, a utm link to measure. And if what you need to give is the whole ticket, that is not a one hundred percent discount but a complimentary ticket, which is issued separately from the dashboard.

Frequently asked questions

What kinds of discount can I create in ENTRÁ?

Two: a percentage or a fixed amount in pesos. Both apply to the subtotal of the whole purchase, not to each ticket, and they can never take the subtotal below zero. Each code belongs to one event and is created from the Descuentos tab of the dashboard.

Does the usage cap count tickets or purchases?

It counts purchases. If someone uses the code and takes four tickets in the same transaction, that is one use. Also, the use is counted when the person starts paying, so it is worth leaving some margin in the cap.

Can someone use an expired or used up code if they know it?

No. The ENTRÁ server checks the code again when creating the payment: if it is paused, expired or over its cap, the purchase is charged at the normal price. It does not depend on what the buyer's browser shows.

How do I know which code brought me the most sales?

In the dashboard's list of codes, each one shows how many times it was used against its cap. If you want to measure channels without giving money away, share the event link with utm parameters: the sales export includes the source and campaign columns.
